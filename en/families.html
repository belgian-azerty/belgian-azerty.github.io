Belgian AZERTY on five Linux families

This project started with Linux Mint and Zorin OS. There are now also files for the other big families of Linux. It is not equally far everywhere. Below you see how far it is for each system.

What does the status mean?

  • Released: there is a version to download. Tested in emulators and on one real laptop.
  • Tested in test containers: tested in a closed-off test system without a desktop. There is nothing to download yet: you build the package yourself, with the steps below. A test on a real desktop will follow.
  • Script: not a package, but a small script. Tested in test containers. Works only on desktops that use Wayland.

The same everywhere

The same three choices as on Mint and Zorin: Caps Lock as on Windows, the Shift+AltGr accents as on Windows, and the layout for a Belgian Apple keyboard. Ctrl+Alt as AltGr comes from keyd, with our rules.

Different from Mint and Zorin

  • No file of the system changes. Our two files go into the folder /etc/xkb.
  • The choices do not appear in your desktop's keyboard settings. You switch them on with one command (below).
  • An X11 session and the text console do not read /etc/xkb. Nothing changes there.

Ubuntu and Debian

Linux Mint 22.3 and Zorin OS 18.1: released (0.9.12). Go to install ›

Ubuntu 24.04 and Debian 13: the same package, tested in test containers. Typing was tested too, on a GNOME desktop without a screen: the same result as on Mint and Zorin. You follow the same steps as on Mint. Debian has keyd itself: type sudo apt install keyd instead of using the PPA.

Moving to Ubuntu 26.04, Linux Mint 23 or Debian 14 later? Install 0.9.12 first. With 0.9.11 or older, the upgrade stops half-way. Tested with a full package upgrade in test containers, not with Ubuntu's or Mint's own upgrade tools.

If the upgrade is already stuck: Problems ›

Fedora

Fedora 44 and 45: tested in test containers. The desktop test found a problem with SELinux. Fix to follow.

Do not install it on Fedora yet. On a Fedora desktop in an emulator, the keyboard typed as on Mint, including keyd and the accents. But SELinux, which is on by default on Fedora, does not let the system's keyboard service read our file in /etc/xkb. Because of that, the system refuses every new layout, even plain Belgian, and the login screen stays US. SELinux was off in the test containers, which is why we did not see it there.

Once there is a fix and it is tested, the steps will be here. If you want to help test, the build steps are already in packaging/OTHER-DISTRIBUTIONS.md.

openSUSE

Tumbleweed and Leap 16.0: tested in test containers, desktop test to follow.

Note: new openSUSE installations also use SELinux. Whether the same problem as on Fedora happens there has not been tested yet. SELinux was off in the test containers. So try it in a virtual machine first.

openSUSE has keyd itself. Type as a normal user:

sudo zypper install rpm-build systemd-rpm-macros git curl
git clone https://github.com/belgian-azerty/belgian-azerty-linux && cd belgian-azerty-linux
SRC=$(rpm --eval %_sourcedir); mkdir -p "$SRC"
curl -L -o "$SRC"/belgian-azerty-linux-0.9.12.tar.gz https://github.com/belgian-azerty/belgian-azerty-linux/archive/refs/tags/v0.9.12.tar.gz
for s in packaging/opensuse/*.spec; do rpmbuild -ba "$s"; done
sudo zypper install --allow-unsigned-rpm $(rpm --eval %_rpmdir)/noarch/*-0.9.12-*.rpm

Then switch the choices on (see "Switching the choices on" below).

Arch

Arch Linux: tested in test containers, desktop test to follow.

Arch has keyd itself. Type as a normal user:

sudo pacman -S --needed base-devel git
git clone https://github.com/belgian-azerty/belgian-azerty-linux && cd belgian-azerty-linux/packaging/arch
(cd belgian-azerty-windows && makepkg -si)
(cd keyd-belgian-windows && makepkg -si)

Good to know: our keyd package switches keyd on straight away, because that is why you install it. On Arch this is unusual.

Then switch the choices on (see below).

Independent systems: Void, NixOS, Gentoo, Slackware, Solus

Script: tested in test containers, X11 still open.

Here there is no package, but a small script. It puts the same two files in /etc/xkb and changes nothing in the system:

git clone https://github.com/belgian-azerty/belgian-azerty-linux && cd belgian-azerty-linux
sudo sh packaging/etc-xkb/be-azerty-etc-xkb.sh install
sh packaging/etc-xkb/be-azerty-etc-xkb.sh status

To remove: sudo sh packaging/etc-xkb/be-azerty-etc-xkb.sh remove. This takes out only our two files.

Good to know

  • Tested with each system's own keyboard library and keyboard data. For Slackware and Solus there is no test container: their own packages were put on another test system. On Slackware 15.0 one check could not run, because the test tool needs a newer version.
  • Only for desktops that use Wayland. An X11 session does not read /etc/xkb, and many of these systems still run X11 (Slackware 15.0 by default). There is no solution for X11 yet.
  • The script does not set up keyd. keyd is in Void, NixOS and Solus; on Gentoo in the GURU overlay, on Slackware on SlackBuilds.org. The rules for keyd are in keyd/be-winaltgr.conf. This was not tested here.
  • On NixOS your configuration manages the /etc folder. Whether a rebuild leaves our files in place was not checked.

Switching the choices on (openSUSE, Arch and the independent systems)

For the whole system, including the login screen and new users, if your system has systemd:

sudo localectl set-x11-keymap be pc105 "" caps:be_windows,be_azerty:accents

Tested in test containers. Without systemd, set the choices in your desktop's keyboard setting.

Not yet tested outside Mint and Zorin

  • A real desktop (GNOME, KDE) and the login screen. GNOME on Wayland should work, but is not tested. For KDE Plasma we do not know.
  • keyd running, so Ctrl+Alt as AltGr while typing.
  • The text console and the disk unlock screen.
  • A real installation or a real PC.
