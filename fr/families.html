L'AZERTY belge sur cinq familles Linux

Ce projet a commencé avec Linux Mint et Zorin OS. Il y a maintenant aussi des fichiers pour les autres grandes familles de Linux. Tout n'en est pas au même point. Vous voyez ci-dessous où en est chaque système.

Que veut dire la situation ?

  • Publié : il y a une version à télécharger. Testé dans des émulateurs et sur un seul vrai ordinateur portable.
  • Testé en conteneurs de test : testé dans un système de test isolé, sans bureau. Il n'y a encore rien à télécharger : vous construisez le paquet vous-même, avec les étapes ci-dessous. Un test sur un vrai bureau suivra.
  • Script : pas de paquet, mais un petit script. Testé en conteneurs de test. Ne fonctionne que sur les bureaux qui utilisent Wayland.

Partout pareil

Les trois mêmes choix que sur Mint et Zorin : Verr. Maj comme sous Windows, les accents avec Maj+AltGr comme sous Windows, et la disposition pour un clavier Apple belge. Ctrl+Alt comme AltGr vient de keyd, avec nos règles.

Différent de Mint et Zorin

  • Aucun fichier du système ne change. Nos deux fichiers vont dans le dossier /etc/xkb.
  • Les choix n'apparaissent pas dans les réglages du clavier de votre bureau. Vous les activez avec une seule commande (ci-dessous).
  • Une session X11 et la console texte ne lisent pas /etc/xkb. Rien n'y change.

Ubuntu et Debian

Linux Mint 22.3 et Zorin OS 18.1 : publié (0.9.12). Vers l'installation ›

Ubuntu 24.04 et Debian 13 : le même paquet, testé en conteneurs de test. La frappe aussi a été testée, sur un bureau GNOME sans écran : le même résultat que sur Mint et Zorin. Vous suivez les mêmes étapes que sur Mint. Debian a keyd lui-même : tapez sudo apt install keyd au lieu d'utiliser le PPA.

Plus tard vers Ubuntu 26.04, Linux Mint 23 ou Debian 14 ? Installez d'abord la 0.9.12. Avec la 0.9.11 ou plus ancienne, la mise à niveau s'arrête à mi-chemin. Testé avec une mise à niveau complète des paquets en conteneurs de test, pas avec les outils de mise à niveau d'Ubuntu ou de Mint. Si la mise à niveau est déjà bloquée : Problèmes ›

Fedora

Fedora 44 et 45 : testé en conteneurs de test. Le test sur bureau a trouvé un problème avec SELinux. Correction à venir.

Ne l'installez pas encore sur Fedora. Sur un bureau Fedora dans un émulateur, le clavier a tapé comme sur Mint, y compris keyd et les accents. Mais SELinux, activé par défaut sur Fedora, empêche le service clavier du système de lire notre fichier dans /etc/xkb. Le système refuse alors toute nouvelle disposition, même le belge tout simple, et l'écran de connexion reste en américain. SELinux était désactivé dans les conteneurs de test, c'est pourquoi nous ne l'avions pas vu.

Dès qu'une correction existe et qu'elle est testée, les étapes seront ici. Si vous voulez aider à tester, les étapes de construction sont déjà dans packaging/OTHER-DISTRIBUTIONS.md.

openSUSE

Tumbleweed et Leap 16.0 : testé en conteneurs de test, test sur bureau à venir.

Attention : les nouvelles installations d'openSUSE utilisent aussi SELinux. Nous n'avons pas encore testé si le même problème que sur Fedora s'y produit. SELinux était désactivé dans les conteneurs de test. Essayez donc d'abord dans une machine virtuelle.

openSUSE a keyd lui-même. Tapez en tant qu'utilisateur normal :

sudo zypper install rpm-build systemd-rpm-macros git curl
git clone https://github.com/belgian-azerty/belgian-azerty-linux && cd belgian-azerty-linux
SRC=$(rpm --eval %_sourcedir); mkdir -p "$SRC"
curl -L -o "$SRC"/belgian-azerty-linux-0.9.12.tar.gz https://github.com/belgian-azerty/belgian-azerty-linux/archive/refs/tags/v0.9.12.tar.gz
for s in packaging/opensuse/*.spec; do rpmbuild -ba "$s"; done
sudo zypper install --allow-unsigned-rpm $(rpm --eval %_rpmdir)/noarch/*-0.9.12-*.rpm

Activez ensuite les choix (voir « Activer les choix » ci-dessous).

Arch

Arch Linux : testé en conteneurs de test, test sur bureau à venir.

Arch a keyd lui-même. Tapez en tant qu'utilisateur normal :

sudo pacman -S --needed base-devel git
git clone https://github.com/belgian-azerty/belgian-azerty-linux && cd belgian-azerty-linux/packaging/arch
(cd belgian-azerty-windows && makepkg -si)
(cd keyd-belgian-windows && makepkg -si)

Bon à savoir : notre paquet keyd active keyd tout de suite, car c'est pour cela que vous l'installez. Sur Arch, c'est inhabituel.

Activez ensuite les choix (voir ci-dessous).

Systèmes indépendants : Void, NixOS, Gentoo, Slackware, Solus

Script : testé en conteneurs de test, X11 pas encore réglé.

Ici, pas de paquet, mais un petit script. Il met les deux mêmes fichiers dans /etc/xkb et ne change rien au système :

git clone https://github.com/belgian-azerty/belgian-azerty-linux && cd belgian-azerty-linux
sudo sh packaging/etc-xkb/be-azerty-etc-xkb.sh install
sh packaging/etc-xkb/be-azerty-etc-xkb.sh status

Pour l'enlever : sudo sh packaging/etc-xkb/be-azerty-etc-xkb.sh remove. Cela n'enlève que nos deux fichiers.

Bon à savoir

  • Testé avec la bibliothèque de clavier et les données de clavier de chaque système. Pour Slackware et Solus, il n'existe pas de conteneur de test : leurs propres paquets ont été mis sur un autre système de test. Sur Slackware 15.0, un contrôle n'a pas pu tourner, car l'outil de test a besoin d'une version plus récente.
  • Uniquement pour les bureaux qui utilisent Wayland. Une session X11 ne lit pas /etc/xkb, et beaucoup de ces systèmes tournent encore sous X11 (Slackware 15.0 par défaut). Il n'y a pas encore de solution pour X11.
  • Le script n'installe pas keyd. keyd se trouve dans Void, NixOS et Solus ; sur Gentoo dans l'overlay GURU, sur Slackware sur SlackBuilds.org. Les règles pour keyd sont dans keyd/be-winaltgr.conf. Cela n'a pas été testé ici.
  • Sur NixOS, votre configuration gère le dossier /etc. Nous n'avons pas vérifié si une reconstruction laisse nos fichiers en place.

Activer les choix (openSUSE, Arch et les systèmes indépendants)

Pour tout le système, y compris l'écran de connexion et les nouveaux utilisateurs, si votre système a systemd :

sudo localectl set-x11-keymap be pc105 "" caps:be_windows,be_azerty:accents

Testé en conteneurs de test. Sans systemd, réglez les choix dans les réglages du clavier de votre bureau.

Pas encore testé en dehors de Mint et Zorin

  • Un vrai bureau (GNOME, KDE) et l'écran de connexion. GNOME sous Wayland devrait fonctionner, mais n'est pas testé. Pour KDE Plasma, nous ne savons pas.
  • keyd en marche, donc Ctrl+Alt comme AltGr pendant la frappe.
  • La console texte et l'écran de déverrouillage du disque.
  • Une vraie installation ou un vrai PC.

Tous les détails : packaging/OTHER-DISTRIBUTIONS.md et HOW-WE-TESTED.md.
